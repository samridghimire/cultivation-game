# WU-466: The season's tasks on the village board

Role: world-ui. Reference: Stardew Valley's community bundles and the town Help Wanted board, mechanics only.

## Why
SEASON-005/WU-462 show the season's three village tasks only on the journal's Today page and as a HUD line when one is left;
nothing in Qingshi itself says the village has asked anything. Review 2026-11-06 note: the HUD's "One more for <season>"
line and Today's task list show in every region, though the tasks pay in Qingshi.

## Spec
1. Qingshi's Hunters' Bounty Board (src/world/interactables/bounty_board.gd `get_options`) gets a first entry
   "Village tasks this <season> (n of 3 done)" when `GameState.season_tasks()` is not empty. Choosing it opens a small modal
   (reuse an existing simple list screen pattern, e.g. how the journal's Today section rows are built in
   src/ui/journal_screen.gd `_build_today`; UIStyle panel) listing the three tasks with check icons, progress "(1/3)", where
   to do each one (a short hint: use `Guidance` if a where-helper exists; else the task's region/place from data if the
   task has one; else nothing), the reward line (`GameState.season_reward_line()`), and the shrine stage
   ("Old Shrine: 2 of 4 stages restored"). Close with Esc/B; focus on the first row (`grab_focus`).
2. When the set is complete the entry reads "Village tasks this <season>: all done" and the modal shows the reward as paid.
3. HUD: the "One more for <season>: ..." Next steps line shows only while the player is in qingshi_village or one route
   away (`Exploration.is_nearby` or the helper FEST-011 uses); the journal Today page keeps the list everywhere but adds
   "(in Qingshi Village)" to the section title when the player is elsewhere.
4. Tests: the board option label for 0/3, 2/3 and 3/3 (static helper, no scene); the HUD line hidden in a far region and
   shown in Qingshi; the modal builds rows for a fixed task list and its first row takes focus (see test_focus_audit.gd).
