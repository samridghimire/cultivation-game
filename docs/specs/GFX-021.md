# GFX-021: Pixel buildings until the pack lands (world-ui)

**Reference:** Wandering Sword's chunky top-down pixel towns (mechanics of presentation only: low-res buildings drawn at an
integer scale with a dark outline and a 2-3 tone shade; never its layouts, names or art).

## Why
Planner shots 2026-10-30 at 1280x800 (hud_arrival.png, fallen_star_market.png): the people are crisp 16x20 pixel figures
(GFX-011/018) and the ground is tiled (GroundTiles), but every building and stall is still smooth vector art from
`src/world/place_art.gd` (`_merchant`, `_workshop`, `_sect_hall`, ...), drawn at full resolution with anti-aliased
ellipses. The two styles clash, and the start village is the first thing a new player sees. Until the owner's pack lands
(GFX-002 is blocked), generate the village buildings as pixel art the same way PixelFigure does.

## Scope (this task): the buildings and stalls of a village
Place kinds (`Interactable.art_kind`): `merchant`, `workshop`, `sect_hall`, `clinic`, `orphanage`, `family_home`,
`bounty_board`, `travel` (the gate, both orientations: sizes 120x40 and 40x120), `auction`.
Nature places (meditation, gather, explore, inheritance, abode, secret_realm, camp) and map landmarks are GFX-022; leave them.

## Design
1. New `src/world/pixel_place.gd`, `class_name PixelPlace extends RefCounted`, `##` doc comment, pure and deterministic,
   no node access (like `PixelFigure`).
   - Templates are text rows, one char per pixel, at **half the place's on-screen size** (drawn at `Sprites.scale()`, which
     is 2 today; read it, never hardcode 2). Palette chars (document them in the doc comment):
     `.` transparent, `o` outline (`2b2118`), `w` wall, `W` wall shade, `r` roof (the place `color`), `R` roof shade
     (`color.darkened(0.3)`), `h` roof highlight (`color.lightened(0.2)`), `d` door / dark opening (`3a2f26`),
     `t` timber (`6e5636`), `T` timber shade, `p` paper/window (`e8dcc0`), `g` gold trim (`c9a24a`), `s` stone (`8a8478`),
     `S` stone shade. Add at most two more if a kind needs them.
   - `static func supports(kind: String) -> bool`
   - `static func texture(kind: String, size: Vector2, color: Color) -> ImageTexture`: picks the template for `kind`
     (and for `travel`, horizontal when `size.x >= size.y`), builds an Image (FORMAT_RGBA8) and caches the ImageTexture in a
     static Dictionary keyed by `kind|color.to_html()|orientation`. Templates have a fixed pixel size per kind (below);
     the caller centres the texture in the place rect, so a place a little bigger or smaller than the template is fine.
   - Template sizes (pixels, before scaling), chosen so `size * Sprites.scale()` fits the smallest data size of the kind:
     merchant 30x28 (a stall: two posts, a striped awning in `r`/`p` stripes, a counter with 3-4 goods in `h`),
     workshop 64x44 (a timber hall, a chimney with an `S` stack, an open forge door glowing `g`),
     sect_hall 78x54 (a two-tier curved roof in `r`/`R`, gold ridge `g`, red pillars, steps in `s`),
     clinic 50x36 (white walls `w`, green roof = color, a hanging gourd sign in `g`),
     orphanage 54x38 (a small temple: tiled roof, red door, two lanterns),
     family_home 40x30 (a cottage with lit `g` windows), bounty_board 34x28 (two posts, a board with 3 pinned `p` notes),
     auction 68x48 (a large hall with a banner), travel 58x18 horizontal / 18x58 vertical (a wooden archway gate with a
     plaque; the vertical one is the same gate seen side-on, not a rotation of the image).
   - Draw the outline on the silhouette edge only (one pixel), shade the bottom/right faces with the `W`/`R`/`T`/`S`
     shades, light from the top-left. Keep roofs readable at 1280x800: no single-pixel detail that matters.
2. Hook: in `src/world/place_art.gd` `PlaceArt.draw(ci, kind, size, color, active)`, before the `match`, add:
   ```gdscript
   if PixelPlace.supports(kind):
       var tex := PixelPlace.texture(kind, size, color)
       var s := float(Sprites.scale())
       var px := Vector2(tex.get_size()) * s
       ci.draw_texture_rect(tex, Rect2(-px / 2.0, px), false)
       return
   ```
   so the Sprites lookup in `Interactable._draw()` (`place_<kind>` keys from data/sprites.json) still wins, and the old
   vector functions stay as dead-code fallbacks for kinds PixelPlace doesn't support. Do **not** delete the vector
   functions for the supported kinds yet (GFX-002/003 may want them for comparison); add a one-line comment that they are
   unused while PixelPlace supports the kind.
   Bottom-align instead of centring if a building would otherwise float above its interact area (the interact Area2D is the
   place rect; the art's base should sit on the rect's lower half). Pick one rule and apply it to every kind.
3. The highlight ring and anchor ring in `Interactable._draw()` stay as they are.
4. Merchant stalls must still differ by color (the place `color` drives the awning `r`), so Fallen Star Market's eight
   stalls stay distinguishable (fallen_star_market.png).

## Tests (`tests/unit/test_pixel_place.gd`, extends TestCase)
- every template row of a kind has the same length, and every char is in the palette;
- `supports()` is true for the 9 kinds and false for `meditation` and `deed_giver`;
- for every place in data/regions.json whose `type` maps to a supported art kind, `texture(...).get_size() * Sprites.scale()`
  is <= the place size + 8 px in each axis (so art never spills far past its interact rect);
- `texture()` returns the same object for the same arguments (cache) and different pixels for two colors;
- the outline: the top-left non-transparent pixel of each texture is the outline color.
