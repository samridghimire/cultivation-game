# GFX-038: The duel stage stays inside its frame

Role: world-ui. Reference: Wandering Sword's duel framing (a clean, bounded backdrop strip; mechanics/presentation only).

## Problem (planner shot 2026-10-31 18:15, `screenshot_first_hour.gd -- --season=Autumn`, combat_report.png, 1280x800)
GFX-036's backdrop draws outside the DuelStage rect. Four pale discs (~180 px wide) hang over the stage edges, past the
modal's left and right borders, and down over the "You" / "Wild Boar" name labels, which become unreadable. The roof
silhouettes also run past the right edge (x 990 on a stage ending at 938). The discs are the "far hills" layer:
`src/ui/duel_stage.gd` `_draw_backdrop()` draws `draw_circle(Vector2(x, horizon + 34 - h/2), 60 + h*0.6, far)`, whole
circles centred near the horizon, in a colour 70% hazed toward the sky, so they read as big balls, not hills.

## Changes (src/ui/duel_stage.gd only, plus its test)
1. Clip: set `clip_contents = true` on the DuelStage in `_init()` so nothing it draws can leave its rect. (Control clipping
   applies to `_draw()`; check that the fighter shake/offset still looks right at the edges.)
2. Hills, not balls: replace the far-hills `draw_circle` with a filled polygon of the circle's *upper* half only, clamped
   so the top never rises above `horizon - top_h * 0.45` (they stay in the lower half of the sky). Build the points with a
   new static `hill_arc(cx: float, base_y: float, r: float, max_h: float, steps: int = 16) -> PackedVector2Array` (pure,
   testable) and draw with `draw_colored_polygon`. Base the arc on `horizon` (not horizon + 34) so nothing is drawn below
   the ground line; the ground band drawn afterwards covers the seam.
   Use a slightly stronger colour (`lerp(haze, 0.55)` instead of 0.7) so the hill line reads as distance against the sky.
3. The default (`_`) silhouette kind has the same whole-circle problem (`draw_circle(Vector2(x, horizon + 20), w, col)`):
   draw it with `hill_arc` too.
4. Roofs: skip a roof piece whose `x + w + 12` exceeds `size.x` (cleaner than relying on the clip).
5. Name labels: make sure the "You" / foe name labels sit below the stage (they are children of the report, not the
   stage); after the clip they must be fully readable. If they overlap the HP bars, move them, don't shrink the font.
6. GFX-036 Follow-up: the stage sky reads `Weather.of(...)` directly, so `--storm` shots show a clear sky. Read
   `World.force_weather` first when a World node exists (use the same lookup GFX-036 added for the world; if it is a
   static/global on World, call it; otherwise add a small static helper `World.weather_today(data, rid, day) -> String`
   that returns the forced weather when set) and use it for `raining`.

## Tests (tests/unit/test_duel_stage.gd, extend the existing file)
- `hill_arc`: all points have `y <= base_y` and `y >= base_y - max_h`; first and last points sit on `base_y`; x spans
  `cx - r .. cx + r`.
- A DuelStage built in a test has `clip_contents == true`.
- With a forced storm (however step 6 exposes it), the stage reports raining (expose `func is_raining() -> bool` if needed).

combat_report_cultivator.png: no shape outside the stage frame, both name labels readable, hills read as a soft distant
ridge, the storm shot shows the dark rainy sky. Say in the commit which shots you viewed.
