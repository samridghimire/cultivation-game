# GFX-252: The rank you wear

Reference: Wandering Sword's readable costumes (look only: rank read at a glance from clothing). Role: world-ui. Size: ~150 lines.

## Why
The sect ladder now works end to end (SECT-035..042), but a promoted disciple looks exactly like a new one: `PlayerLook.of`
(src/world/player_look.gd) only sets the robe from the sect and the sash from alignment. A promotion should be visible on the map
and on the sect cards.

## Build
1. `PlayerLook.of`: add `"trim"` to the returned dict: `Color(0,0,0,0)` (none) for rogues and rank 0; for rank 1 a silver
   `Color("c8d0d8")`, rank 2 gold `Color("e8c76a")`, rank 3+ jade `Color("6fd3a8")`. Put the three colors in a `const RANK_TRIM`
   array so tests and other code read them. Rank comes from `c.sect["rank"]` (check the actual key in Sects; don't guess).
2. `src/world/pixel_figure.gd`: when `look.trim.a > 0`, colour the robe's collar/neck row and the hem row pixels (the template rows
   documented at line ~51: "Body rows 8-19 per direction: neck, shoulders, ..., hem") with the trim colour instead of the robe
   shade, for every direction and walk frame. Include the trim in the texture cache key (line ~234) or figures will reuse a stale
   texture. NPC looks without `trim` are unchanged.
3. `src/world/player.gd`: the placeholder `_draw()` path (used when the sprite path fails) draws a 1 px trim line at the hem
   ellipse in the same colour, so both paths agree.
4. Sect cards (`src/ui/sect_card.gd` `draw_figure`, the trial arena and the promotion card) already take a `look` dict: pass the
   player's `PlayerLook.of` so the promotion card shows the new trim (the promoted rank, i.e. after the promotion).

## Tests (`tests/unit/test_player_look.gd`, create if missing)
- Rogue and rank-0 member: trim alpha 0. Rank 1/2/3: the RANK_TRIM colours.
- PixelFigure: a rank-1 look's texture differs from the rank-0 look's (compare a hem pixel), and two calls with the same look hit
  the cache (same texture instance, if the cache exposes that; otherwise skip).
