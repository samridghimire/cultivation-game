# GFX-069: No label sits on another

Role: world-ui. Reference: Stardew Valley / Wandering Sword, where a name is only drawn where it can be read (mechanics only).

## Problem (planner shots 2026-11-05, `screenshot_first_hour.gd`)
- `-- --great --region=azure_peak` at 1280x800: "Great Cloud Crane (Weak)" is drawn on top of "Hermit Gu (Retired Azure
  Cloud Elder)". Roamers and NPCs move, but `Interactable.spread_on_screen` (src/world/interactables/interactable.gd ~290)
  is only re-run on some triggers, so moving labels collide after the last pass.
- `-- --arrival-card` at 1280x720: the WU-441 prompt chip "[E] Wandering Merchant" covers the "Village Pond Jetty" label
  (WU-441 Follow-up); "Hunters' Bounty Board" sits inside the targeted stall's highlight box.
- Hall labels sit on top of GFX-068's flagstone court, which is fine, but the court must count as ground, not a blocker.

## Build
1. Re-run the spread when anything with a label moves: in world.gd (wherever `spread_on_screen` is called today), call it
   at most every 0.25 s while any roamer or NPC with a drawn label moved more than 4 px since the last pass (track last
   positions; no per-frame cost when nothing moves). Keep the existing priority order (highlighted, then places before
   NPCs, then nearest).
2. Great beasts rank right after the highlighted target (a gold beast name should win over a villager's name). Add the
   rule to the sort in `spread_on_screen`; ordinary roamers rank with NPCs.
3. The prompt chip is a blocker: pass the chip's screen rect (Hud.prompt_rect result, already computed in hud.gd ~889) in
   `occupied` so a label under it is nudged or faded. Expose it from the HUD (`Hud.current_prompt_rect() -> Rect2`, empty
   Rect2 when no chip) and have world.gd include it. Avoid a feedback loop: the chip's own target label is hidden while the
   chip shows (WU-441), so it is not in the list.
4. The target highlight box (the yellow rect around a targeted place) is a blocker for other labels too.
5. A faded label stays readable on approach: when the player is within 60 px of a faded node it ranks as highlighted.

## Tests (tests/unit/test_label_layout.gd or a new test_label_spread.gd)
- Pure: two moving rects that start apart and then overlap get separated on the next pass (call the pure helper twice).
- A great-beast roamer outranks an NPC label in the sort (build two Interactables in the test, as existing label tests do).
- With a chip rect in `occupied`, a label under it gets an offset or is faded.
- The re-spread throttle: no pass when nothing moved, one pass within 0.25 s after a 5 px move.
