# CAL-010: The village almanac (a daily omen)

Role: systems. Reference: Stardew Valley's daily luck from the fortune-teller on TV, and the traditional Chinese almanac
that marks each day auspicious or not for certain work (mechanics only: one small, readable daily modifier that makes a
player plan "today is a good day to fish"). Planner default (small, see DESIGN.md "CAL-010"). Size: one run.

## Why
Days in the first hour feel alike: the Today card lists herbs and weather, but nothing makes *this* day special. A tiny
daily omen, known in advance, gives a reason to pick fishing today and gathering tomorrow, and fits the genre's feel.
It must stay small: never touch qi, breakthroughs or combat (pacing is the owner's call, F-005d).

## Build
1. **data/almanac.json** (new file, loaded and validated by GameData like the others; `_doc` at the top):
   `{"_doc": "...", "omens": [{id, name (<= 30 chars, e.g. "Good for fishing"), text (<= 120 chars, the almanac's line),
   weight (>= 1), effects: {...}}]}`. Allowed effect keys (validate: unknown key = error, values in range):
   - `fishing_mult` 1.0..1.3 (multiplies the catch odds the way `Weather.fishing_multiplier` does)
   - `gather_bonus` 0..0.25 (chance of one extra unit of a gathered herb, same pattern as `SeasonTasks.gather_bonus`)
   - `gift_favor` 0..3 (extra favor on a liked or neutral gift; not on a disliked one)
   - `sell_mult` 1.0..1.1 (shop sell prices, the player selling)
   - `practice_mult` 1.0..1.25 (technique practice progress)
   - none (`{}`): a plain day.
   Ship 7 omens: one per effect key with a modest value (fishing 1.2, gather 0.15, gift 2, sell 1.05, practice 1.15) plus
   two plain days ("An ordinary day", "Neither good nor ill") with the highest weights, so about 2 days in 5 are plain.
   C-349 writes more texts later.
2. **src/core/systems/almanac.gd** `class_name Almanac` (static, RefCounted, `##` header):
   - `static func omen_for(data: GameData, day: int, salt: int) -> Dictionary`: weighted pick seeded from
     `hash(str(salt) + ":" + str(day))` with a local RandomNumberGenerator (like `Weather._rng`), so it never draws
     from GameState.rng (determinism, CLAUDE.md rule 4) and is the same each time you ask. `salt` is a per-session
     number so every life gets its own calendar: use an existing persistent seed if GameState has one (grep
     `world_seed`/`session_seed`); if none exists, use `hash(player.id)` or `hash(player.name + str(birth day))`
     (no save change).
   - Accessors `fishing_mult(omen) -> float`, `gather_bonus(omen) -> float`, `gift_favor(omen) -> int`,
     `sell_mult(omen) -> float`, `practice_mult(omen) -> float`, each 1.0/0 for a plain day.
   - `static func line(omen: Dictionary) -> String`: "Almanac: Good for fishing. <text>" ("" never; plain days print
     their own text).
3. **Hooks in GameState** (thin, one line each; keep the effect where the existing modifier of the same kind is applied):
   - fishing (game_state.gd ~1401, the `mult` line): `* Almanac.fishing_mult(omen)`.
   - `gather` (~1327, next to the terrace bonus): an extra unit with `Almanac.gather_bonus(omen)` chance, drawn from
     `rng` only when the bonus is > 0 (so plain days keep the rng sequence unchanged).
   - `give_gift` (~2295): `+ Almanac.gift_favor(omen)` when the taste is not a dislike.
   - selling (find the sell price helper used by the shop screen): `* Almanac.sell_mult(omen)`, rounded down, at least
     the old price.
   - `practice_technique` (~2794): progress `* Almanac.practice_mult(omen)`.
   Add `GameState.today_omen() -> Dictionary` for the UI.
4. **Where the player sees it**: the journal Today card's first lines (where the weather/"Today in <region>" line is built:
   grep `DayDigest`/`today_lines`) gets `Almanac.line(omen)`; the message log posts the line once a day at dawn only when
   the omen is not plain (one line, category "info"). Tomorrow's omen is also in the calendar's "Tomorrow" reminder
   list if one exists there (VillageCalendar), as "Tomorrow is good for fishing.". Calendar day cells are WU-513.
5. **Earnings**: `Earnings.earning_options` multiplies the fishing row by `fishing_mult` and the gathering row by
   `(1 + gather_bonus)` for today, so the card stays honest on a lucky day (pass the omen in or compute it from `today`).

## Tests (tests/unit/test_almanac.gd, plus integration)
- `omen_for` is deterministic for the same (day, salt), differs across salts for some day in 30, and over 1000 days
  every omen appears with a share within +-5 points of its weight share.
- Validation rejects an unknown effect key and an out-of-range value (build a bad GameData dict like other validation tests).
- GameState integration (test_game_session.gd): on a day forced to the fishing omen (pick a salt/day found by a loop in
  the test), a fishing trip's `mult` is 1.2x the plain day's (test the helper the trip uses, or compare Earnings rows).
  A plain day leaves the rng sequence unchanged for `gather` (same seed, same result as before the change).
- Earnings: the fishing row is 1.2x on the fishing-omen day.
