# GFX-218: Nights that read as night

Role: world-ui. Reference: Stardew Valley's blue evening tint with warm lit windows; Wandering Sword's lantern-lit towns (look only, no art).

## Why
Planner shot 2026-11-20 06:10 (`screenshot_first_hour.gd -- --region=qingshi_village --skip-dusk`, skip_night_qingshi_village.png):
GFX-217's night (phase 0.5) reads as a flat grey dim, not a moonlit night. Only a few house windows glow faintly; the
stalls, temple, workshop, sect hall and lanterns on places do not. The time-skip card ("Meditating, 3 days") that the shot
opens is not visible at all. GFX-217's own Follow-ups say the same, plus the Fallen Star skip shot never rendered in time.
Reviewer (2026-11-20): the overlay uses the lighter 0.25 dim for every skip, even when no cycle plays (days < 1).

## What to build
1. **Moonlit tint** (`src/core/systems/day_light.gd`): night key `Color(0.45, 0.5, 0.75)` multiplied by the season base reads
   grey because the dim overlay adds grey on top. Make the night key bluer and a little darker (start at `Color(0.38, 0.45, 0.78)`)
   and make dusk warmer (`Color(1.0, 0.78, 0.6)`). Add `static func night_blue(c: Color) -> bool` test helper or simply test that
   `tint_at(0.5, Color.WHITE)` has `b > r + 0.3` and `b > g + 0.25`. Keep morning exactly white at 0 and 1 (existing tests).
2. **More things glow** (`src/world/night_glow.gd` `setup`): today only `lantern` and `house` landmarks. Also take the region's
   places (world.gd passes them; the place's `pos` and drawn size from PlaceArt/PixelPlace): every place whose art is a building
   (house, hall, temple, workshop, shop/stall, auction house, inn: use the same kind/art key list PlaceArt draws as a roofed
   building; name it `GLOW_KINDS` in night_glow.gd) gets one window/door glow at its lower centre, radius 12; stalls get one
   lantern spot at the awning's corner, radius 10. Cap 40 spots per region (nearest-first is not needed; take the first 40).
   Make the glow warmer and brighter: core `Color(0.55, 0.35, 0.12, 0.5 * strength)` with the 3 rings; still additive.
3. **The card shows**: find why `hud._show_time_skip` in the `--skip-dusk` shot leaves no card (likely the overlay waits for
   its fill tween, or `close` from the previous shot hides it; check `settle` frames). Fix the shot (not the game) if the game
   path works: verify by playing a real 3-day meditation in a headless test that the overlay is visible during the cycle.
4. **Dim only with a cycle** (`src/ui/time_skip_overlay.gd:75`): use 0.25 only when the world actually plays a cycle
   (days >= 1 and not reduced motion and ambient effects on); otherwise the old 0.45. Pass that fact in from the HUD rather than
   re-deriving it twice (one `plays_cycle: bool` argument or field).
5. **Fallen Star shot**: `--region=fallen_star_market --skip-dusk` timed out in GFX-217's run. Find the slow step (likely the
   market's crowd/MarketLife rebuild per shot) and make the shot finish under 120 s; if it is a game-side slowness over 200 ms,
   note it under Follow-ups instead of fixing.

## Tests (tests/unit/test_day_light.gd and the existing NightGlow test file, or a new test_night_glow.gd)
- `tint_at(0.5, WHITE)` is clearly blue (as above); `tint_at(0.35, WHITE)` has `r > b`.
- `NightGlow.setup` with a region dict holding one house landmark, one workshop place and one stall place returns
  `spot_count()` = 2 + 1 + 1; 60 building places cap at 40.
- The overlay's dim alpha is 0.45 for a skip with `plays_cycle = false`, 0.25 with true.

  Describe each in the commit message (one line each).
- reduce_motion / Ambient effects off: no cycle, no glow (unchanged).
- tools/test.sh prints ALL CHECKS PASSED. No balance impact (no `tools/balance.sh`).
