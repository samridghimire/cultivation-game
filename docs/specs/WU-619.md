# WU-619: The sect's year on the calendar

Reference: Stardew Valley's calendar (mechanics only: you plan your week around marked days). Role: world-ui (one small pure
function in `VillageCalendar`, the rest is drawing). Size: ~200 lines.

## Why
A sect disciple's month has fixed beats (the monthly lecture, the monthly duty, the yearly contest month), but the calendar (J ->
Calendar, `src/ui/calendar_screen.gd`) shows only village things: markets, festivals, birthdays, crops. The Sect page lists this
month only. A member should open the calendar and see when the sect needs them.

## Build
1. `src/core/systems/village_calendar.gd`: new `static func _sect_dates(out: Array[Dictionary], data: GameData, c: CharacterData,
   total_today: int, start: int, end: int) -> void`, called from `upcoming()` when `c != null and not c.is_rogue()`. Entries use
   the existing `{day, kind, text, region}` shape (region = the sect's home region, the same id `Sects.report` uses):
   - kind `"lecture"`: on the first day of each month in [start, end) whose lecture is not yet attended (for the current month
     use `Sects.check_lecture(c, data, day) == ""`; future months are always unattended). Text: `"Lecture: <lecture name>"`.
     If today is inside a month whose lecture is unattended, put the entry on today instead of the (past) first day.
   - kind `"duty"`: on the last day of each month in range, only when `Sects.monthly_duty(c, data) > 0`. Text for the current
     month: `"Sect duty due (<done>/<needed> days)"` from `duty_progress`; later months: `"Sect duty due"`.
   - kind `"sect_contest"`: on the first day of the contest month (`Sects.contest_def(c, data).month`) when it falls in range and
     `Sects.check_contest(c, data, that_day)` is "" (so a rank too high or an entry already made shows nothing). Text:
     `"Outer-sect contest (all month, at the hall)"`. If today is inside the contest month and entry is open, place it on today.
   Use `Calendar` helpers for month starts (`month_start` exists in VillageCalendar); never hard-code 30.
2. `src/ui/calendar_screen.gd`: add the three kinds to `KIND_NAMES` ("Lecture", "Sect duty", "Contest") and to `short_label`;
   give each an icon the way other kinds get theirs (find where `market`/`birthday` icons are chosen, likely `HudIcons`; reuse
   an existing glyph such as the sect banner for contest, a scroll for lecture, a broom/tool for duty if one exists; otherwise
   draw a 20 px placeholder in the same style). The legend lists them only when present that month (as other kinds do).
3. Dawn reminders: `VillageCalendar.reminders()` already turns entries into dawn lines for some kinds. Add `sect_contest` (the day
   the month opens: "The outer-sect contest is open this month at the <hall name>.") and `duty` (3 days before month end while
   duty is short; skip if `Sects.duty_reminder` already posts the same thing: check and don't double up).

## Edge cases
- Rogues: no sect entries at all. Leaving a sect removes them at once (no cache).
- A sect without a lecture or contest block: those kinds are skipped.
- Next-month view (PgDn) shows next month's lecture/duty/contest entries.

## Tests (`tests/unit/test_village_calendar.gd`, new functions)
- Rogue -> no lecture/duty/sect_contest entries.
- Azure member on day 0 -> a lecture entry today, a duty entry on the month's last day (if the sect has a duty), and, when the span
  covers month 3, a contest entry on its first day.
- After attending this month's lecture -> no lecture entry this month, one next month.
- After `Sects.enter_contest` -> no contest entry that year.
