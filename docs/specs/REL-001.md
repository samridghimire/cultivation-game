# REL-001 Autosave (systems)

## Problem
Progress is only saved from the pause menu (pause_menu.gd) or F5 quick save (world.gd:66). Closing the window loses everything,
and there is no autosave on travel, breakthrough or long meditation. Unacceptable for a Steam release.

## Change
1. src/autoload/save_manager.gd: `const AUTOSAVE_SLOT := "autosave"` and `func autosave() -> bool` that calls
   `save_game(AUTOSAVE_SLOT)` only when `GameState.player != null and GameState.player.alive` and not mid-combat/encounter
   (`GameState.pending_encounter == ""`), and never more than once per in-game day (remember `GameClock.total_days` of the last
   autosave). Returns whether it saved. Posts nothing to the message log (silent), but a small "Saved" toast is out of scope.
2. Triggers (GameState, after the action fully resolves): region change (travel), successful breakthrough, and in
   `_pass_time` whenever a month boundary is crossed (the monthly sim hook already exists, see `_on_days_advanced`). Keep the
   calls in GameState via `SaveManager.autosave()`; respect a new setting `autosave` (bool, default true) if settings live in a
   ConfigFile (look at src/ui/settings*.gd / the settings autoload for how `show_hints` is stored) and add a checkbox for it to
   the settings screen.
3. Quit: in the world scene (src/world/world.gd) handle `NOTIFICATION_WM_CLOSE_REQUEST`: autosave (bypassing the once-a-day
   limit), then `get_tree().quit()`. Set `get_tree().auto_accept_quit = false` while the world scene is active and restore it
   on exit so the main menu still closes normally.
4. Load screen (src/ui/load_screen.gd): the autosave slot appears like any slot, labelled "Autosave". `list_slots()` must
   include it; check the load screen test still passes. "Continue" on the main menu (if it exists) should pick the most recent
   of all slots by save time.
5. Tests must not leave files in user://saves: in tests, use the existing pattern test_load_screen_with_saves.gd uses
   (it writes and deletes a real save) and delete the autosave slot afterwards.

## Tests (tests/unit/test_autosave.gd)
- autosave() with a live session writes the slot; a second call the same day returns false; after advancing a day returns true.
- Dead player: autosave() returns false.
- Travelling to another region autosaves (slot exists afterwards); setting off: no autosave.
- Loading the autosave slot restores region and qi.

## Acceptance
`tools/test.sh` passes; closing the game window and relaunching shows the autosave in Load.
