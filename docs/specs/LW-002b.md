# LW-002b: Sect clashes and the sect's call (systems)

Part 2 of LW-002. Part 1 (src/core/systems/sect_factions.gd) gives each sect a `strength` from its living NPC members and
recruits rogues monthly. Now righteous and demonic sects fight, and the player's sect can call on them.

## Data
`data/sects.json` top-level `factions` gains an optional `clash` block (document it in the `_doc`, validate in
`SectFactions.validate`):
```json
"clash": {"monthly_chance": 0.08, "casualties": 1}
```
- `monthly_chance` (0..1): each month, for each hostile pair, the chance they clash.
- `casualties` (int >= 1): how many of the loser's living NPC members die.
- Hostile pairs: every pair of sects where one has `"alignment": "righteous"` and the other `"demonic"` (`SectDef.alignment_tag`,
  loaded from the sect's `alignment` field). Neutral sects (Myriad Treasure Pavilion) never clash.

`data/sect_missions.json`: a new optional mission field `requires_flag` (world flag id that must be set for the mission to be
offered). Document it in `_doc`, validate it is a non-empty string if present. Add two missions:
- `answer_azure_call` (sects: azure_cloud_sect, kind guard, enemy: an existing Qi Refining demonic foe beatable around QR3-5,
  e.g. a Blood Lotus scout/raider; check tests/sim/simulate_combat.gd and pick one rated Even for a QR4 typical player, or add
  `blood_lotus_raider` to enemies.json at qi_refining stage 3, non-lethal), min_realm qi_refining, days 5, contribution 150,
  `requires_flag: "sect_call_azure_cloud_sect"`, rewards `{"alignment": 10, "clear_flag": "sect_call_azure_cloud_sect",
  "reputation": {"azure_cloud_sect": 20}}`, cooldown_days 0.
- `answer_blood_lotus_call` (sects: blood_lotus_sect), the mirror image against an Azure Cloud foe of similar strength,
  alignment -10, `clear_flag: "sect_call_blood_lotus_sect"`.

## Core
1. `Effects.apply`: new key `clear_flag` (String): `flags.erase(id)`. Document it wherever the Effects keys are listed (grep
   `set_flag` in data `_doc`s / effects.gd) and allow it in any Effects key validator.
2. `Sects.available_missions(c, data, flags: Dictionary = {})`: skip missions whose `requires_flag` is not truthy in `flags`.
   `Sects.check_mission(c, data, mission_id, flags: Dictionary = {})`: return "Your sect has no need of this now." when the
   flag is missing. Update the callers (mission_board.gd, sect_hall.gd, guidance.gd, GameState.take_mission, complete_mission)
   to pass `GameState.world_flags` (core callers get flags passed in; guidance gets a `flags` param with default {}).
3. `SectFactions.hostile_pairs(data) -> Array` of `[righteous_id, demonic_id]`, sorted for determinism.
4. `SectFactions.clash(data, npcs, rng) -> Array[Dictionary]`: for each hostile pair, with `monthly_chance`: strengths sA, sB
   (`strength()`); skip if both 0; winner = A if `rng.randf() < sA / float(sA + sB)` else B. Kill `casualties` random living
   NPC members of the loser (`members()`, rng pick; never the player, who is not in `npcs`) via `Npcs.die(c, "fell in battle
   against the <winner name>")`. Return events `{winner, loser, dead_ids: Array, text, category: "danger"}` with text like
   "The Azure Cloud Sect and the Blood Lotus Sect clashed at the border. The Blood Lotus Sect lost 1 disciple."
5. `GameState._sect_factions_month()`: after recruitment, run `SectFactions.clash`. For each event: if the player's sect is
   the winner or loser, post the text and set `world_flags["sect_call_<player sect id>"] = true`, then post
   "Your sect calls on its disciples. A new mission waits on the mission board." (category warning). Otherwise post nothing,
   but post a death line for any dead NPC that `Npcs.is_newsworthy` says the player knows ("News arrives: X fell in battle
   against the ..."). Keep the last clash text in `SectFactions.rumors` input? Optional: skip.
   world_flags is already saved, so no save change.

## Tests (tests/unit/test_sect_factions.gd)
- hostile_pairs returns only righteous x demonic pairs.
- clash with monthly_chance 1.0 (override `data.sect_factions["clash"]` in the test) and a seeded rng kills exactly
  `casualties` members of the loser, none of the winner; a sect with 0 strength vs one with strength always loses.
- monthly_chance 0 → no events.
- Validation errors for chance outside 0..1 and casualties < 1.
- Effects `clear_flag` removes a flag.
- A mission with `requires_flag` is hidden from available_missions and refused by check_mission until the flag is set.
- GameState integration (tests/unit/test_game_session.gd style): player in azure_cloud_sect, force a clash (chance 1.0), run
  `_sect_factions_month()`; the flag is set and `answer_azure_call` is available; completing it clears the flag.
