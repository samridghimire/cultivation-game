# WU-625: The pond fisher, landed (C-405 rescue)

Role: world-ui. Reference: Stardew Valley's villagers at their work (mechanics only).

## Why
C-405 (a named Qingshi pond fisher + a `firewood` lend yield) has failed to land three times. The data is done on branch
`origin/claude/C-405-pond-fisher-3` (5 files, +21 lines: data/npcs.json, data/items.json, data/family.json,
data/encounters.json, tests/unit/test_lend_a_hand.gd). What blocks it is not content: adding one named villager changes
which generated villagers exist / their ids in Qingshi, their stands move, and two layout tests then fail. That means the
generated-villager layout only passes by luck of the current seed. Fix the layout, then land the data.

The worker's notes on that branch (commit message): after adding `fisher_pei`
- `test_clean_first_frame` (`test_no_person_label_sits_on_a_figures_head_in_qingshi`): generated "He Ying"'s label sits
  on a figure's head at (605,580);
- `test_goal_marker.test_person_labels_keep_off_the_players_figure`: "Wenren Ning"'s label overlaps the player;
- `test_first_hour.test_hints_player_acts_on_next_steps`: the 2-month hints run now only logs `lend` actions
  (Mo/Ling/Ma/Pei), never `talk`.
Moving the fisher's own spot (6 tries) did not change the label failures.

## Steps
1. `git checkout -b claude/WU-625-pond-fisher origin/main`, then `git checkout origin/claude/C-405-pond-fisher-3 -- data/ tests/unit/test_lend_a_hand.gd`
   (take only those files; check `git diff origin/main --stat`). Run tools/test.sh and confirm the 3 failures above.
2. **Label clearance as a placement rule** (src/world/world.gd `_build_generated_npcs`, src/core/systems/npcs.gd
   `spread_stands` or a new pure helper): after the generated villagers' stands are settled and spread, any generated
   villager whose name-label rect (the same rect the tests use: see `_head()` in tests/unit/test_clean_first_frame.gd and
   the label rect in tests/unit/test_goal_marker.gd) would cover another figure's head, or the player's figure at the
   spawn point, is nudged to the nearest free candidate (try offsets of 24-48 px in 8 directions, keep it on walkable
   ground with `SectCourt.settle_stand`, never into a place's avoid radius). Deterministic: no rng, same order every day.
   Prefer a pure static helper `Npcs.clear_label_overlaps(stands: Array[Vector2], heads: Array[Vector2], label_size: Vector2) -> Array[Vector2]`
   with its own unit test (two stands whose labels collide come out apart; a clear layout comes out unchanged).
   Generated ids/saves must not change (no SAVE_VERSION bump).
3. **hints-player test**: `talk` vanished because the first Next-steps line is no longer "Talk to Elder Mo" for 8 weeks
   once there is one more friend to lend to. Check `FirstHour.hints_log["acted"]` on the new data: if Elder Mo's goal is
   still the first line on day 1, the sim should still log `talk` in week 1 (find why it doesn't: likely the lend branch
   matches first). Fix the sim/test so the assertion stays meaningful ("the newcomer reaches Elder Mo in the first two
   months"); do not just delete it.
4. tools/test.sh green. Render `--focus=<fisher_id>` (hud_arrival) and `--lend=<fisher_id>` for qingshi_village and open
   both: fisher on the jetty, labels clear. Commit `[WU-625] The pond fisher, landed` and say in the body that it carries
   C-405's data (the planner marks both done).
