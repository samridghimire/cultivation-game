# LOG-003: A log worth reading (systems)

Reference: Immortal Life's daily log, which tells you what changed today and leaves forecasts to the calendar (mechanics only).

## Why
QA-211 measured the default first hour at **12.1 log lines/month** against the 9.5 target. LOG-002 thinned the artifact
line to weekly; its own Follow-ups name the two remaining loud templates:
- the nightly **"Tomorrow: <omen>."** forecast lines (8+ templates, ~0.4-0.6/month each), which repeat what the HUD's Today
  card and the journal's almanac block (`GameState.almanac_lines`, `Almanac.tomorrow_line`) already show;
- **"Sect mission: X. You face the Y. (You: N hp ...)"** (0.45-0.72/month per mission), which repeats the combat report
  card that opens right after it (`GameState` ~3089 passes "Sect mission: %s. " as the fight intro).
QA-211 also found that log_noise.gd attributes some 'Tomorrow:' lines to `combat` (topic read from `history.back()`).

## Changes
1. **Evening forecasts.** Find where the "Tomorrow: ..." reminders are posted to the log each night (grep `"Tomorrow: "` in
   src/core/systems/guidance.gd ~379-480 and its callers in game_state.gd). Post a forecast to the log only when it
   matters for a plan the player can act on: a market day, a great beast day, a festival, or an omen the player's current
   season task or hint depends on (fishing omen while a catch task is open, gathering omen while a gather task is open).
   Plain flavour omens stay on the Today card and the journal only. At most one forecast line per night: when several
   qualify, join them into one line ("Tomorrow: market day in Fallen Star Market; good for fishing.").
2. **Mission fights.** When the combat report will open for a sect-mission fight (the normal case in the UI), the log gets
   only the outcome line(s) it already posts, not the "Sect mission: X. You face the Y." intro. Keep the intro when the
   fight is resolved without a report (headless sims, auto-resolve) so the log still says what happened. Use whatever flag
   the combat report path already exposes; do not add UI code to core.
3. **log_noise.gd topic.** Attribute each counted line to the category it was posted with (`EventBus.post(text, category)`),
   not `history.back()`. Small change in tests/sim/log_noise.gd.

## Tests (tests/unit/test_game_session.gd or the existing almanac/guidance tests)
- A night with only a flavour omen tomorrow posts no "Tomorrow:" line; the journal's almanac lines still include it.
- A night before a market day posts exactly one "Tomorrow:" line; a night with market day + fishing omen + an open catch
  task posts one joined line.
- A sect-mission fight with the report path on does not post "You face the"; with it off it still does.
