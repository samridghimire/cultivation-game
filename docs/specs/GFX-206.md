# GFX-206: Every name on its owner

Role: world-ui. Reference: Wandering Sword's town labels (look only: a name sits right over the person it names).
Source: planner shot 2026-11-19 00:10 `hud_arrival.png` (Qingshi, day 0, 1280x800) plus the GFX-202 and WU-567 Follow-ups.

## What is wrong
1. **Elder Mo's name floats ~60 px over his head.** He stands just under the "Meditation Rock" place label, so
   `LabelLayout.person_offset` (label_layout.gd ~102) slides his label sideways up to 40 px, then lifts it 4..80 px until it
   clears every place rect. It ends above the place label, so the order reads "Elder Mo / Meditation Rock / (Mo)". The
   WU-567 gold chevron is drawn between the two labels. A newcomer's first goal is this man.
2. **Patriarch Lin's label sits on the Azure Cloud Hall stair** (Azure Peak arrival shot) — the same lifted-label case.
3. **"Village Herb Slope (0/3)" hides behind the region arrival banner** at the top of the Qingshi arrival shot: the banner
   is not one of the HUD's `occupied_rects()`, so the label is laid out under it.

## Change
A. `LabelLayout.person_offset(label, feet_y, place_rects)`: cap the lift. Order of tries:
   1. no move (clear) -> ZERO;
   2. sideways up to 24 px (was 40) with no lift;
   3. lift at most `PERSON_MAX_LIFT := 16.0` px (with the same sideways tries);
   4. **below the feet**: label top at `feet_y + 2` (use the currently unused `feet_y`; caller passes
      `node.position.y + node.size.y / 2.0`, already done in `clear_person_labels`), sideways tries as in 2;
   5. still blocked: return ZERO and let the **place label yield** (B).
   Keep the WU-522 rule "never drops onto their own head": below-the-feet is under the figure, not on it.
   `Interactable.spread_labels` clamps `label_offset.y <= 0` for persons (line ~262) and `person_label_tick` does
   `_label_avoid.y = minf(_label_avoid.y, 0.0)`: allow the below-feet offset (a flag on the node, e.g. `_label_below := true`,
   or allow y >= the below-feet offset only). Don't break WU-555's easing: a walking person who flips above/below should ease, not jump.
B. When a person's label still hits a place label (step 5), move the **place** label instead: down under the place's art by
   the overlap (place labels "never move" since WU-481 only between ambient re-spreads; this is a one-time layout at region build).
   Only for persons with an `npc_id` (named villagers), not roamers.
C. The region arrival banner: `hud.occupied_rects()` includes the banner's rect while it is visible, and the HUD calls the
   world's re-spread once when the banner hides (there is already a `_spread_on_screen()` path; use a signal or the existing
   hook that HUD modals use). A label under the banner moves down (WU-269/281 screen clamp already handles a blocker).
D. Check that WU-567's goal marker (src/world/goal_marker.gd) follows the label: the chevron sits above the person's label
   when the label is above, and above the head when the label went below the feet.

## Tests (tests/unit/test_label_layout.gd and test_region_label_collisions.gd)
- person_offset with a place rect directly above the head: result lift <= 16 px or the label is below `feet_y`.
- person_offset with place rects above and below: falls to ZERO (caller then moves the place label).
- Build qingshi_village (as test_region_label_collisions does): Elder Mo's drawn label rect is within 24 px (vertically) of
  his sprite rect and overlaps no place label; same for Patriarch Lin in azure_peak.
- HUD: with the arrival banner showing, `occupied_rects()` contains a rect covering it.
