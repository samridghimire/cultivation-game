# ENC-002: Encounters and the combat sim respect `min_stage`

**Why:** encounters can only be gated by major realm (`min_realm`), so a foe that is fair at Qi Refining 5th layer also
ambushes a 1st-layer newcomer (QA-007g and QA-025 Follow-ups: the marsh corpse puppet / blood lotus scout can't be
gated, Nascent Soul encounters are judged at stage 0). Sect missions already have `min_stage` (sects.gd ~447), but the
combat sim ignores it, so its "entry" column for missions is measured at stage 0 (it reported the purge mission at 32%
although QA-007g gated it at stage 1, where it is 69%).

## Data: data/encounters.json
Document a new optional field in `_doc`, right after the min_realm/max_realm sentence:
"min_stage (optional, ENC-002, needs min_realm): the encounter is only eligible at or above that stage of min_realm
(0-based: Qi Refining 3 = the 4th Layer); a player in a higher realm always qualifies."
Don't add `min_stage` to any encounter in this task (content tunes it later, C-013).

## Core
- `src/core/systems/exploration.gd` `eligible_encounters` (~65): after the `min_realm` check add
  ```gdscript
  if e.has("min_stage") and c.realm_index == data.realm_index_of(e["min_realm"]) and c.stage < int(e["min_stage"]):
  	continue
  ```
  Extract it as `static func realm_allows(c, data, e: Dictionary) -> bool` (min_realm, min_stage, max_realm) with a `##`
  comment if that reads cleaner; keep behaviour identical otherwise.
- `src/core/game_data.gd` `_validate()` encounter loop (~420): if `min_stage` is present it needs `min_realm`, must be an
  int >= 0 and < `realms[realm_index_of(min_realm)].stage_count()`. Message style: "Encounter '%s' has min_stage %d
  outside its min_realm's stages" / "Encounter '%s' has min_stage without min_realm".
- Grep for other code that reads encounter `min_realm` for eligibility (e.g. Guidance, the explore-site event list,
  `tests/unit/test_data_references.gd`) and apply `min_stage` there too if it decides whether the encounter can happen.

## Sim: tests/sim/combat_balance.gd
- `appearances()` (~164): each entry gains `"stage"`: the encounter's `min_stage` (0 if absent) for encounter and
  encounter-choice rows (a choice's own `requires.min_realm` higher than the encounter's resets the stage to 0), and the
  mission's `min_stage` for mission rows.
- `rate()` (~189): `entry`, `talisman`, `bare` and `veteran` use `appearance.get("stage", 0)` instead of stage 0
  (`peak` stays the realm's last stage). Update the column header/comment wording ("entry" = at its gate).
- Check tests/unit/test_combat_balance.gd and test_first_hour_economy.gd guards still pass; they may need their
  expectations raised for rows that were measured too low. Don't loosen any guard.
