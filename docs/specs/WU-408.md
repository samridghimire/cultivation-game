# WU-408: Who is speaking (portraits in dialogue and NPC menus)

Role: world-ui. Reference: Wandering Sword's talk boxes, where the speaker's pixel portrait sits beside the line (layout idea only;
our art is our own generated PixelFigure).

## Why
Planner shot elder_mo_dialogue.png (2026-10-30 18:15): Elder Mo's dialogue and every NPC/place menu are a plain text box.
The world is pixel art now, but talking to someone shows no face. A portrait makes every conversation read as *this person*.

## What
1. `Interactable.portrait_texture() -> Texture2D` (src/world/interactables/interactable.gd), default `null`.
   - `npc.gd`: `PixelFigure.frame(figure_look(), "down", 0)`.
   - `deed_giver.gd` (Elder Mo, Headman Zhou...): the same look it draws in `_draw` (`PlaceLooks.figure_look(look, color)`).
   - Merchants/stalls and other places: `null` for now (no portrait column; layout must not leave a gap).
2. `DialogueWindow.set_portrait(tex: Texture2D)` and `ChoiceMenu` (src/ui/choice_menu.gd, `open_for(source)` already gets the
   node): when `tex` is non-null, a left column with a framed portrait at 3x (`PixelFigure.SIZE * 3`, `TEXTURE_FILTER_NEAREST`,
   same frame style as `character_sheet.gd` ~line 90), the existing text column to its right. `null` hides the column.
   The dialogue window keeps its 680 px width; the text column shrinks by the portrait width so lines still wrap inside.
3. The HUD passes the source: find where `EventBus.dialogue_requested` is handled in hud.gd and where the dialogue is started
   from an interactable (GameState dialogue start / the interactable that emitted it). If the dialogue request has no source
   node, add an optional `portrait: Texture2D` argument path in the HUD (remember the last interactable the player activated:
   `hud._last_source` set in `open_for`'s caller) rather than changing the core signal's meaning.
4. Optional, only if it fits: a 2-frame "talking" bob (the portrait shifts 1 px every 0.25 s while the text is new, stops after
   1 s; nothing when `Settings.reduce_motion`).

## Tests (tests/unit/test_dialogue_portrait.gd or extend the existing dialogue/choice-menu tests)
- `npc.portrait_texture()` is non-null and its size is `PixelFigure.SIZE`; a merchant/place returns null.
- ChoiceMenu opened for an NPC shows the portrait column; opened for a place it is hidden (`visible == false`) and the buttons
  keep their full width.
- DialogueWindow: `set_portrait(null)` hides the column; the text label's wrap width + portrait column <= the window width.
- Focus still lands on the first choice (`grab_focus`), gamepad unchanged.
