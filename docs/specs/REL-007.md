# REL-007: Saves survive crashes (systems)

Steam players will kill the game mid-save (Steam Deck sleep, power loss). Today `SaveManager.save_game` (src/autoload/
save_manager.gd ~112) opens the slot file with WRITE, which truncates it first, so a crash mid-write destroys the save, and a
corrupt slot silently disappears from the load screen (`read_meta` returns {} and `list_slots` skips it).

## Changes (src/autoload/save_manager.gd)
1. Atomic write: write the JSON to `<slot>.json.tmp`, close the file (let it go out of scope or call `file.close()`), check
   the write succeeded (`file.get_error() == OK` before closing), then if `<slot>.json` exists rename it to `<slot>.json.bak`
   (DirAccess.rename_absolute, replacing an older .bak: remove it first), then rename the .tmp to `<slot>.json`. On any
   failure return false and leave the old save in place.
2. `func _read_payload(slot) -> Dictionary`: parse `<slot>.json`; if it is missing or not a Dictionary with a `game` key, try
   `<slot>.json.bak`; return {} if both fail. Add `"from_backup": true` to the returned dict when the backup was used.
   `load_game` and `read_meta` use it. When `load_game` loads from the backup, post
   `EventBus.post("Your last save was damaged; loaded the one before it.", "warning")` after the session starts.
3. `list_slots`: a `<slot>.json` that exists but can't be read and has no usable backup is listed as
   `{"slot": slot, "damaged": true, "name": slot, "saved_unix": 0, "alive": true}` so the player can see and delete it.
   `.tmp` and `.bak` files never appear as slots (they don't end with `.json`; keep it that way).
4. `is_loadable` is false for damaged slots; `most_recent_living_slot` skips them.
5. `delete_save` also removes `<slot>.json.bak` and a stray `.tmp`.

## Load screen (src/ui/load_screen.gd)
A damaged slot shows "<slot>: damaged save" with Load disabled and Delete enabled (same pattern as REL-002's fallen slots).

## Tests (tests/unit/test_save_manager.gd or a new test_save_safety.gd; use a test slot name and clean up)
- save twice → `.bak` exists and holds the first save; the slot loads the second.
- Overwrite `<slot>.json` with garbage → `load_game` succeeds from the backup and the meta says from_backup.
- Garbage and no backup → `list_slots` lists it with damaged=true, `is_loadable` false, `delete_save` removes it.
- A leftover `.tmp` file is not listed as a slot.
