# FH-004b Threat prompt (world-ui)

FH-004 (on main) made a lethal foe rated Dangerous stop the explore and wait: GameState sets `pending_threat`, posts "You sense
a X nearby..." and emits `EventBus.threat_sensed(enemy_id)`. Nothing listens yet, so today these threats are silently skipped
(the next explore clears `pending_threat`). This task adds the prompt. Keep it small: reuse ChoiceMenu.

## 1. A source object for ChoiceMenu
ChoiceMenu (src/ui/choice_menu.gd) renders any `source` that has `display_name`, `menu_options() -> Array[Dictionary]` and
optionally `on_menu_closed()`. It always appends a "Leave" button and focuses the first enabled button.

Add `src/ui/threat_prompt.gd`: `class_name ThreatPrompt extends Node` (a plain Node, never added to the tree is fine, but
keep one instance as a child of the HUD so it's freed with it).
- `var display_name: String` set in `prepare(enemy_id: String)` to `"A %s is near" % enemy name`.
- `menu_options()` returns, in this order:
  1. `{"label": "Slip away (1 day)", "action": GameState.face_threat.bind(false)}`
  2. `{"label": "Fight it (%s, %d%% to win)" % [UIStyle.fight_label(...), pct], "action": GameState.face_threat.bind(true)}`.
     `UIStyle.fight_label` (FH-010) already appends "to the death" for lethal enemies; compute pct with
     `Combat.win_chance(GameState.player, GameState.data, enemy)` exactly as GameState._resolve_explore_enemy does.
- `on_menu_closed()`: if `GameState.pending_threat != ""` call `GameState.face_threat(false)`. So "Leave" and ui_cancel both
  mean "slip away" and a threat can never stay pending behind a closed menu.

## 2. HUD wiring (src/ui/hud.gd)
- Connect `EventBus.threat_sensed` in the same place `encounter_choice_requested` is connected (~line 143).
- `_on_threat_sensed(enemy_id)`: close the time-skip overlay if visible (`_time_skip.close()`; explore passes time *before*
  the threat is sensed, so the overlay may be up), `_close_screens()`, `_threat_prompt.prepare(enemy_id)`,
  `_choice_menu.open_for(_threat_prompt)`, `_update_modal()`.
- The fight that follows opens the combat report as usual (face_threat(true) calls fight()). Check that the choice menu closes
  before the report shows (ChoiceMenu closes after the action unless `keep_open`).

## 3. No stale threats (src/autoload/game_state.gd)
The reviewer noted only explore/encounter paths clear `pending_threat`. Also clear it at the top of `travel()` and in
`cultivate()`/`cultivate_in_seclusion()` (one line each: `pending_threat = ""`). The prompt is modal, so this is a safety net.
