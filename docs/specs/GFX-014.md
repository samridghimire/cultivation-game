# GFX-014: The duel stage in pixel art, and banners that wait for the report (world-ui)

**Reference:** Wandering Sword's small pixel fighters squaring off (mechanics/presentation only, no art copied).

**Seen by the planner (2026-10-29 18:15, `screenshot_first_hour.gd`, combat_report.png):** the world now uses GFX-011's
16x20 `PixelFigure` people, but the fight report's duel stage (`src/ui/duel_stage.gd`) still draws the smooth vector
pawn (`_draw_person`) and a barely visible rectangle beast (`_draw_beast`). And a "New" banner ("You are strong enough to
travel to Withered Bone Marsh ...") is drawn over the top of the open report, hiding its "Victory: Wild Boar" title.

## 1. Fighters from PixelFigure
- `_draw_fighter`: when no sprite is mapped (`tex == null`), draw a `PixelFigure.frame(look, "side", frame)` texture
  instead of `_draw_person`, scaled by an integer factor (3x at 1280x800; use `Sprites.scale()`-style integer scaling,
  nearest filter), feet at `feet`. The player uses the same look dictionary the world player uses (`PlayerLook` /
  whatever GFX-011 passes for the player); the foe (a cultivator) uses a look built from `FOE_ROBE` and a dark sash.
  Mirror the foe so the two face each other. Walk frames: frame 0 when idle, alternate 1/2 during the lunge (`_offset`
  changing) so the attack reads as a step.
- Beasts: add a generated 24x16 side-view quadruped template to `PixelFigure` (`static func beast_frame(fur: Color,
  index: int) -> ImageTexture`, text-template rows like the people: body, head with an ear, four legs, tail; 2 frames).
  Fur colour: brown default; grey for ids containing "wolf", dark for "boar", rust for "tiger"/"fox" (a small id->colour
  table in duel_stage.gd is fine). Keep `_draw_beast` only as the fallback if the template fails.
- Keep tint/flash/alpha/tilt/shake (WU-397 reduce-motion must still work): apply `tint` as the modulate of `draw_texture_rect`.
- Cache generated textures (PixelFigure already caches people; do the same for beasts).

## 2. Banners never cover an open modal
- In `src/ui/hud.gd` (the `_banner` owner) or `banner.gd`: while any HUD modal screen is open (the same check the HUD uses
  to block input / `_add_screen` screens and the combat report), queue `announce` calls instead of showing them, and play
  the queue (in order, each with its hold time) once the last modal closes. Milestone/"Breakthrough!" ordering rules from
  RV-002 stay as they are. If a queue is simpler in Banner itself, expose `set_held(held: bool)`.
- Unit test (tests/unit/): with a modal open, `announce` does not show; closing it shows the queued banner. A pure helper
  for the queue is fine to test without a scene.
