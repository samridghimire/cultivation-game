# FH-010 Menu clarity pass for newcomers (world-ui)

Four small fixes in world interactables, all found in a first-hour audit.

1. **Sect join reasons** (src/world/interactables/sect_hall.gd:21-23): disabled "Join the X" entries give no reason. Append
   the reason like other menus do: `label += " (%s)" % check["reason"]` when `not check["ok"]` (check how npc.gd formats
   disabled reasons and match it exactly; if menu entries support a `"reason"` key, use that instead).
2. **Court/Propose clutter** (src/world/interactables/npc.gd get_options): "Court X" and "Propose as ..." show disabled at favor
   0 on every NPC, including elders. Hide both entries entirely while the NPC's favor is below the courtship threshold in
   data/family.json (use the same constant/field Family.check_court uses; don't hardcode a number), or when the NPC is not a
   possible partner at all (Family.check_partner fails for reasons that can't change: gender, close kin, child). Keep showing
   them disabled-with-reason once favor reaches the threshold.
3. **Anchor entries** (src/world/interactables/interactable.gd ~63-66): "Bind artifact anchor here (1/1 used)" is enabled and
   clicking only posts a warning. When all slots are used, show it disabled with the reason "All N anchor slots are bound;
   release one first". Hide "Release artifact anchor" when it is the player's only bound anchor (a newcomer can otherwise drop
   their only respawn point on day 1).
4. **Lethal wording**: menu entries that show a fight danger label (mission_board.gd ~152-158, deed givers, inheritance and
   secret realm entries, the NPC "Turn hostile" fights) should append " - to the death" when the enemy is `lethal`, so "Deadly"
   is not confused with "you will die". Add one helper `static func fight_label(c, data, enemy: Dictionary) -> String` in
   src/ui/ui_style.gd (or next to where danger labels are formatted) that returns e.g. "Dangerous, to the death" and use it in
   those places.
