# GFX-106: Icons you can tell apart

Role: world-ui. Reference: Wandering Sword's item icons (readable small pixel glyphs per item kind), mechanics only:
no art copied. Planner shot 2026-11-09 `inventory.png` (default `screenshot_screens.gd` run): Ancestor Incense, Dragon Boat
Charm, Five-Colour Thread, Green Dumpling, Jade Rabbit Lantern, Moon Cake, Osmanthus Wine and Paper Kite all show the same
round pill or pouch blob in a 12x12 glyph drawn at 2x, so the inventory reads as a list of identical dots.

## What to build

### 1. New glyph kinds in `src/ui/item_icon.gd`
Add 10 entries to `GLYPHS` (12 rows of 12 chars, same `o`/`a`/`b`/`.` alphabet) and a `BODY` colour for each:

| kind | look | BODY |
|---|---|---|
| `food` | a round bun/dumpling with a pleated top, or a cake slice | `e8d2a0` |
| `drink` | a small wine jar: round belly, narrow neck, a cloth-tied stopper | `b0763c` |
| `lantern` | a round paper lantern with top/bottom caps and a hanging cord | `d9453a` |
| `incense` | three thin sticks in a small burner, a wisp on top | `c89a6a` |
| `charm` | a knotted cord charm: a diamond knot with a tassel below | `c8403c` |
| `kite` | a diamond kite with a cross spar and a tail | `e8b04a` |
| `thread` | a spool or a coil of twisted thread | `b07ad8` |
| `trophy` | a curved horn/tusk | `e8e0cc` |
| `meat` | a meat cut on a bone | `b8564a` |
| `grain` | a tied sack with a few grains at the mouth | `c8a86a` |

Keep each glyph inside the 12x12 grid with a 1-px outline like the existing ones. Tint: `food`, `drink`, `lantern`, `charm`,
`thread` use the item's own `color` / hashed tint the way pills and herbs do (`body.lerp(tint, 0.7)`), the rest keep BODY.

### 2. Choosing the kind
`kind_of(item)` keeps today's order, with two changes:
1. First (after the per-id glyph check): if the item has a non-empty `icon` field, return it.
2. Before the final `usable -> pill` / `pouch` fallbacks, map tags: `trophy` -> trophy, `meat` -> meat, `grain` -> grain,
   `keepsake` -> charm. Do **not** guess from item names in code; the per-item choice is data (C-339).

### 3. The `icon` field (data)
- items.json: optional `icon` (string). Document it in the items.json `_doc` ("icon: optional glyph kind for the generated
  item icon: one of pill, herb, ore, beast_material, spirit_stone, weapon, armor, accessory, talisman, manual, scroll, fish,
  pouch, food, drink, lantern, incense, charm, kite, thread, trophy, meat, grain").
- Validate in `GameData._validate()` next to the other item checks: unknown value -> error naming the item. The list of valid
  kinds lives in core (a `const ITEM_ICON_KINDS: PackedStringArray` in game_data.gd or an item-def helper), because core can't
  read `ItemIcon` (UI). Add a unit test in `test_item_icon.gd` (or the existing icon test) that every kind in
  `ITEM_ICON_KINDS` has a glyph and a BODY in `ItemIcon`, so the two lists can't drift.
- Set `icon` yourself on the 8 items in the planner's shot (ancestor_incense incense, dragon_boat_charm charm,
  five_colour_thread thread, green_dumpling food, jade_rabbit_lantern lantern, moon_cake food, osmanthus_wine drink,
  paper_kite kite) so the result is visible now; C-339 does the rest.

### 4. Bigger icons in rows
Inventory, shop and crafting rows draw the 12x12 glyph at `ZOOM := 2` (24 px) inside a ~36 px slot. Use 3x (36 px slot ->
make the slot 40-42 px, or keep the slot and draw at 3x with 2 px padding) only if the row height allows without clipping
names at 1280x720; otherwise keep 2x and say so in the commit. The detail panel's big icon stays as it is.

## Tests
- `kind_of` returns the `icon` value when set, the tag mapping for trophy/meat/grain/keepsake, and today's kind otherwise
  (pill for a usable item with no tags, pouch for the rest).
- Every glyph is exactly 12 rows of 12 chars from the allowed alphabet.
- Validation rejects `"icon": "banana"`.

## Acceptance
- Render the default `screenshot_screens.gd` run at 1280x800 and 1280x720 and open `inventory.png` and `shop.png`: the
  eight items above show eight different, recognisable icons; nothing clips.
- `tools/test.sh` prints ALL CHECKS PASSED. No balance run (no numbers change).
