# GFX-195: The ridge's white hatches, for real

Role: world-ui. Reference: Wandering Sword's mountain maps (look only: solid, readable snow and rock, no noise patterns).

## Problem (planner shot 2026-11-18 06:10, region_myriad_peaks_ridge.png, Spring, 1280x800)
GFX-191 hid the map.high snow *drifts* outside Winter, but the Spring ridge still shows 3-4 white patches filled with
**diagonal stripes** (right of the Scorched-Scroll Pedlar ~x 1000-1080 y 300-360 on screen; bottom-centre ~x 560-640
y 650-700). They read as a rendering glitch, not snow.

The source is the ground texture, not the drifts: `GroundTiles._alpine_life` (src/world/ground_tiles.gd ~540) paints
Spring "snow" blobs with `_blend_blob(..., Color("eef3f7"), 0.9)`, and `_blend_blob` (~518) gives every blob a
"ragged rim" from `edge := 0.78 + 0.22 * sin(float(x) * 0.7 + float(y) * 0.5)`. That sine of `x*0.7 + y*0.5` is a set
of diagonal bands, so a strong white tint becomes a striped hatch. The same rim is on the hollows, lichen, moss, needle
drifts and winter frost blobs (lines ~545, 548, 579, 581, 593), where it is fainter but still a diagonal pattern
(Azure Peak uses the same passes).

## Do
1. Replace the sine rim in `_blend_blob` with a per-cluster hashed rim (the same idea GFX-193 used for grass patches):
   work in 2x2 pixel clusters; a cluster is inside when `d < 0.82 + 0.18 * h` where `h` is an integer hash of
   (blob seed, cluster x, cluster y) mapped to 0..1 (use PERF-009's `_ihash`, no string hashing in the pixel loop).
   No alpha ramp: the tint strength is flat inside the blob, plus one dithered border ring of clusters at half strength.
   Keep it on raw bytes if PERF-009 already converted that pass; otherwise write it on raw bytes
   (`img.get_data()` / `Image.create_from_data`) so the pass does not get slower (check with
   `tests/sim/region_load_times.gd -- --region=myriad_peaks_ridge,azure_peak --passes`).
2. Spring snow patches on scree read as snow: flat `eef3f7` body (strength 1.0), a 1 px `b8c4d0` shadow on the lowest
   row of clusters of each patch, and fewer of them on a sparse meadow (`maxi(2, n / 4)` when the meadow density < 1.0,
   the ridge; Azure Peak keeps `maxi(3, n / 2)`). Summer/Autumn: no snow blobs (unchanged).
3. Look for any other `sin(` used as a 2-D pattern inside a per-pixel ground loop in ground_tiles.gd (line ~605 is a 1-D
   edge wave along x and is fine) and list any you find in the commit's Follow-ups rather than fixing them all.

## Tests (tests/unit/test_ground_tiles.gd)
- `_blend_blob` output has no diagonal banding: on a 64x64 flat image, blend one blob of radius 24 at full strength and
  assert that along the blob's interior every 2x2 cluster is either fully tinted or untouched (no row of alternating
  stripes), and that the pixel count is deterministic for the same seed.
- Same seed -> byte-identical texture; different region id -> different rim.
- Spring ridge (density 0.3) yields fewer snow blobs than Azure Peak (density 1.0) for the same map size.
