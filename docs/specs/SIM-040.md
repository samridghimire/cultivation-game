# SIM-040: The hints player goes home

Role: systems (sim tooling, no game change unless the diagnosis proves a game gap). Reference: Stardew Valley's letters and
calendar that pull you back to town; Tale of Immortal's home village (mechanics only).

## Why
SIM-039 (docs/specs/SIM-037-result.md "After GUIDE-298..300 and FOLK-057"): in 12 months the hints player never makes a
first congratulation (0/6), never finishes a full season set (0/6), and never goes home to Qingshi. GUIDE-299 added
`Guidance.home_call_hint` ("Home to Qingshi (5 days): congratulate Xiao Ling on Qi Refining; 1 autumn task left (14 days)"),
but its spec item 5 (the sim acts on it) was never done: `FirstHour._act_on_hint` (tests/sim/first_hour.gd ~2532) has no
`"Home to Qingshi ("` branch, so the line is dropped. Both season-task lines (`Guidance.season_task_hint`) and the
congratulate line only appear while the player stands in Qingshi, so a sect disciple can never act on them.

## What to build (tests/sim/first_hour.gd, tests/sim/simulate_first_hour.gd)
1. **Trace first.** With `--firsts 6 12 --firsts-trace`, check that "Home to Qingshi (" appears among seed 1's weekly top
   lines after sect join (days 35-330). Paste 3 sample weeks in the commit. If it never appears, it is a game gap: find
   which condition in `home_call_hint` fails (route days > `family.json home_call.max_route_days` 8? no friend news? the
   season window?) and fix that smaller side in guidance.gd with a unit test in tests/unit/test_guidance*.gd. Otherwise
   it is a sim gap; do (2)-(4).
2. **Act on the home call.** In `_act_on_hint`, a line beginning `"Home to Qingshi ("` calls `_walk_to(gs, c, SeasonTasks.REGION)`
   and returns `"home_call"` when `gs.current_region == SeasonTasks.REGION` afterwards, else "". Add `"home_call"` to
   `PRESS_COST` if that table needs an entry (use the travel cost already used for `"travel"`).
3. **Stay for the week's errands, then go back.** On a week that starts in Qingshi after a `home_call`, the normal loop
   already reads Qingshi's lines (Congratulate, Season task, lend, tea). Make sure the sim **returns to the sect hall**
   afterwards: if the member is in Qingshi, no Qingshi line in the top 5 is actionable (or two weeks have passed since
   arriving), walk back to `Sects.home_region(gs.data, String(c.sect["id"]))`. Check how the sim currently gets a member
   back to the hall after other trips (grep `home_region` in first_hour.gd) and reuse it; do not add a second mechanism.
4. **Hunt tasks.** The `"Season task: "` branch (~2674) only finds catch/gather tasks via `_season_gather`. Add: a line
   `"Season task: hunt "` that is not `"too strong for now"` walks to the task's region (`SeasonTasks.where` names it;
   read `t["target"]` and find a region whose roamers or explore pool has it, the way the sim's "Easy fight" branch finds
   a fight, ~2744) and fights the target until the task count is met or the sim loses once; return `"season_hunt"`.
5. **Rows.** Add to `FIRSTS` in simulate_first_hour.gd: `"first trip home"` (first `home_call` action) and
   `"first practice level"` (the first technique practice level-up: GUIDE-298 Follow-up, so level-ups stop counting as
   dead days; read it from the technique's practice level in `_firsts_now`). A dead stretch now also ends on these.

## Acceptance
- `--firsts 6 12` before (main) and after rows in the commit message for: first trip home, first congratulation, first
  full season set, first shared meditation, first practice level, and the five longest dead stretches.
- Target: first congratulation and a full season set each in >= 3/6 seeds by day 365, no dead stretch over 90 days in
  5/6 seeds. If missed, say which line the sim saw and why it could not act, under `Follow-ups:` (don't tune the game).
- `tools/test.sh` prints ALL CHECKS PASSED. No balance.sh run needed for sim-policy-only changes; if (1) changes
  guidance.gd, it is a hint change (no balance check either).
- Append a short "After SIM-040" table to docs/specs/SIM-037-result.md (same form as SIM-039's).
