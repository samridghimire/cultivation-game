# SIM-025: The test player crafts and trades

Role: systems (tests/sim tooling only; no game code). Reference: none.

## Why
GUIDE-280 (e64bffb) traced the longest quiet stretch of each seed (default start, 4 seeds x 1095 days: 48/42/34/65 days).
Seed 4's stretch (days 713-778) is a five-month peak cultivation whose other hint lines are a sect trial, a craft line (Swift Wind
Talisman) and a trade line; the hints player in tests/sim/first_hour.gd ignores all three, so the sim reports emptiness that a
real player would fill. Before the planner files game changes from quiet-stretch numbers, the sim must act on what the game offers.

## Steps
1. Read `quiet_stretches.gd --weeks` output for seed 4 (and the other seeds) and list every hint line in the longest stretches
   that `_act_on_hint` (tests/sim/first_hour.gd ~line 2289) does not handle. Paste the list in the commit.
2. Add branches to `_act_on_hint` for, at least:
   - **Craft lines**: find the exact text in src/core/systems/guidance.gd (grep "craft", "Craft ", "talisman"). When the bag holds
     the materials, call the same GameState action the crafting screen uses (grep `func craft` in src/autoload/game_state.gd);
     otherwise, if the line names where the material grows or is sold, gather or buy it (reuse the existing gather/buy branches).
   - **Trade / sell lines**: reuse the existing `"Sell your"` branch; add the other trade wordings the list shows (e.g. a
     commission or a market price line) by calling the matching GameState action.
   - **Sect trial lines**: take the trial (GameState action used by the sect screen) only when the line's rated odds are Easy or
     Even (90+ or 70-89 in 100; parse the "N in 100" like the fight branches do).
   Each branch returns its action name like the others, so `--weeks` prints it.
3. `quiet_stretches.gd --weeks`: count how often each new branch fired per seed and print it under the seed's table.
4. Re-run `quiet_stretches.gd` (same arguments as GUIDE-280) and paste, per seed: longest stretch before/after and the top hint
   lines of the new longest stretch.
5. The hints player feeds balance baseline sections (grep `first_hour` / `presses` in tools/balance.sh). Refresh only those
   sections with `tools/balance.sh --section <name>` and explain every moved line in one sentence each.

## Tests
No unit test needed for sim code, but `tools/test.sh` must pass (the sims are parsed during import).

## Acceptance
- The commit lists the unhandled lines found, the new branches, the before/after table, and the refreshed sections.
- Any line the sim still cannot act on because the game has no action for it goes under `Follow-ups:` (the planner turns those
  into game tasks).
- Under ~300 changed lines.
