# WU-028: Calmer screen behind modals; character sheet buttons (world-ui)

**Why (WU-021 Follow-ups):** with any modal open, the HUD status panel and message log still draw under it (WU-021 raised
panel opacity to 0.97 to hide the bleed), and the character sheet's Recharge/Train/Family/Close buttons sit cramped right
under its scroll area.

## HUD (src/ui/hud.gd)
- `_update_modal()` already computes "any modal is open" and emits `EventBus.ui_modal_changed`. Store that bool and, when
  it is true, hide the status panel, the HUD hint lines and the bottom message log (the nodes built in
  `_build_status_panel` / `_build_log`; keep references to them). Show them again when it turns false.
- Exceptions: keep them visible while only the **time-skip overlay** or the **banner** is up (they are not modals for this
  purpose; check what `_time_skip.visible` contributes and exclude it here), and never touch the death screen logic.
- The world itself (player, places) stays drawn; only the HUD panels hide.

## Character sheet (src/ui/character_sheet.gd)
- Put the action buttons in their own HBoxContainer row with `separation` 12 and a 10-12 px spacer (or margin) above it,
  so they never touch the scroll area; the row must stay on screen at UI scale 115% (WU-026's fit test covers screens; add
  the sheet if it isn't there).
- Focus order unchanged (gamepad): the first button is reachable from the scroll area with ui_down.

## Tests
- test_hud (or the nearest HUD test): opening the inventory hides the status panel and log; closing shows them again;
  a time-skip overlay alone does not hide them.
- test_steam_deck_layout.gd / WU-026's fit test: character sheet buttons inside the viewport at 100% and 115%.
