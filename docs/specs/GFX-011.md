# GFX-011: Pixel-art people until the pack lands

Role: world-ui. Reference: Wandering Sword (small chibi-proportioned top-down people, readable by robe colour and
silhouette, 2-3 frame walk cycles). Mechanics/look only, no copied art. Same idea as GFX-007's generated ground: real pixel
art built in code, no binary file, replaced later by a data edit in data/sprites.json (GFX-004).

## Why
Planner region shots (2026-10-29): the player and every NPC are smooth vector "pawns" (a trapezoid robe, a circle head),
which clash with the new pixel ground (GFX-007) and landmarks (GFX-008). People are what a player looks at most.

## What to build
1. **`src/world/pixel_figure.gd`** (`class_name PixelFigure`, RefCounted, rendering only, `##` doc comment):
   - `const SIZE := Vector2i(16, 20)`; templates as `PackedStringArray` rows of exactly 16 chars, one char per pixel:
     `.` transparent, `o` outline, `s` skin, `h` hair, `r` robe, `R` robe shade, `b` sash, `e` eye, `f` feet/shoes.
   - Templates for `down`, `up`, `side` (right-facing; `left` = horizontal mirror of `side`), each with 3 frames: stand,
     step A, step B (legs/hem pixels shift by one). Two head variants via a `style` key: `bun` (hair knot on top) and
     `long` (hair down the back). A `child` variant uses a 16x16 body (shorter robe) drawn on the same 16x20 canvas,
     bottom-aligned. Design the art yourself; keep a 1-px dark outline so figures read on any ground colour.
   - `static func frame(look: Dictionary, dir: String, index: int) -> ImageTexture`, memoised like `GroundTiles.cached`
     (key = colours + style + child + dir + index % 3). `look` keys: `robe`, `sash` (Colors, as `PlayerLook.of`), `skin`,
     `hair` (Colors), `style` ("bun"/"long"), `child` (bool). Missing keys fall back to constants. Robe shade =
     `robe.darkened(0.25)`, outline = `Color("2b2118")`.
   - Pure and deterministic: no randomness, no node access.
2. **Player** (`src/world/player.gd`): when `_draw_sprite` returns false, draw `PixelFigure.frame(...)` at integer scale
   `Sprites.scale()` (2), feet on the current hem line (y = 12), instead of the polygon robe/head. Facing -> dir as
   `_draw_sprite` already computes; frame index `int(_time * 6.0)` while moving, 0 when still. Keep the shadow, aura,
   companion, bob and celebration shake. `PlayerLook.of` gains `skin` (constant `Color("e8c9a0")`), `hair`
   (`Color("2a2018")`) and `style` (`bun` for male, `long` for female; read `c.gender`).
3. **NPCs** (`src/world/interactables/npc.gd`): when `Sprites.first(sprite_keys())` is null, draw a PixelFigure instead of
   `PlaceArt`'s person shape. Look from the NPC's CharacterData (`GameState.npcs`/people, as `label_text` finds it):
   robe from its sect's `robe_color` when it is a sect member, else one of 6 muted robe colours picked by
   `hash(npc_id) % 6`; hair grey `Color("b8b8b8")` from age 60, else dark; style by gender; `child` when under 12.
   Named NPCs without CharacterData (data/npcs.json fixed people) use their place `color` as robe. The facing of a
   wandering NPC follows its wander direction (down when idle). Keep the label, rival colour and "!" badge as they are.
   Drawing must stay cheap: no per-frame Image work (only cached textures), many NPCs share textures.
4. data/sprites.json mapping (`player_*`, `npc_<id>`, `npc`) still wins over the generated figure.

## Tests (tests/unit/test_pixel_figure.gd, new)
- every template row is 16 chars and every template has SIZE.y rows; every char is in the palette;
- `frame()` returns a 16x20 texture; same look -> same instance (cache); different robe -> different texture;
- the robe colour appears in the image and the four corners are transparent;
- `left` frame image is the horizontal mirror of `side`/right;
- `child` figures have no opaque pixel in the top 4 rows;
- `PlayerLook.of` returns `style` "long" for a female character and "bun" for a male.
