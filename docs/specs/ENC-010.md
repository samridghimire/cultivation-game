# ENC-010: Happenings rest between repeats

Role: systems. Reference: Tale of Immortal (a region's small events come back only after a while, so each one still reads as
news). Mechanics only.

## Why
Planner traces 2026-10-29 12:10 (`tests/sim/simulate_curious_years.gd -- 1 36 --trace=139`, sect, and `--trace=141 --rogue`):
once the player reaches Foundation in Qingshi, the same few village beats return month after month:
- `city_pickpocket_caught` ("Fingers brush your sleeve...") m21, m27, m28, m31, m33, m35 (seed 139) and m30, m33, m36 (141);
- `village_hopeful_youths` ("Two youths from the next field...") m22, m23, m25, m26, m29, m30;
- `village_rogue_begs_pointers` m15, m19, m32 / m26, m29, m34; `village_beast_at_the_fold` m16, m25 / m28, m35.
`Exploration.freshness` fades a beat the more it is met, but `_keep_non_fight_share` rescales the faded non-fight beats back
to their old share, so in a region with a small pool of Foundation beats the same two or three still win most days.

## What to build
1. **Data** (`data/encounters.json`): top-level `rest_days` (int >= 0, default 0 when absent = today's behaviour; set it to
   **120**), and an optional per-encounter `rest_days` (int >= 0) that overrides it (0 = never rests). Document both in
   `_doc` and validate them in `GameData._validate()` (non-negative ints). The rest applies only to encounters that fade
   (`Exploration.fades(e)` true: not `repeatable`, not plain gathering); fights and repeatable gathering never rest.
2. **State** (`src/core/character_data.gd`): `encounter_last_day: Dictionary` (encounter id -> total day last met), in
   `to_dict`/`from_dict` with default `{}` (older saves load; every beat counts as rested). No SAVE_VERSION bump is needed
   for a defaulted field; if you bump anyway, add a fixture (CLAUDE.md rule 5).
3. **Rules** (`src/core/systems/exploration.gd`):
   - `note_met(c, e, day: int = -1)`: also store `c.encounter_last_day[id] = day` when `day >= 0`. Update every caller to pass
     the current total day (GameState passes `GameClock.total_days`; sims pass their day).
   - `static func resting(c: CharacterData, data: GameData, e: Dictionary, day: int) -> bool`: true when `day >= 0`, the
     encounter fades, its rest (per-encounter or top-level) is > 0, it was met before, and `day - last < rest`.
   - `eligible_encounters(..., day: int = -1)`: skip resting encounters (before they enter `unfaded_total`, so the
     non-fight share no longer refills them). With every non-fight beat resting, the day falls through to the region's
     quiet day as it does today. Pass the day from every caller of `eligible_encounters`/`roll_encounter` in GameState
     and the hint code (`Guidance`/`Exploration` helpers that count unmet happenings must not treat a resting beat as unmet).
4. The explore footer/odds text (if it lists "Often quiet N%") keeps working: compute it with the same day.

## Tests (tests/unit/test_exploration.gd or a new tests/unit/test_encounter_rest.gd)
- A beat met on day 100 with rest 120 is not eligible on day 150 and is eligible again on day 220.
- `rest_days: 0` on an encounter overrides the top-level value; a `repeatable` encounter and a fight never rest.
- `day = -1` (callers that pass no day) keeps today's behaviour.
- `encounter_last_day` round-trips through `to_dict`/`from_dict`; a dict without the key loads as `{}`.
- GameData rejects a negative or non-int `rest_days`.
- A GameState integration test (tests/unit/test_game_session.gd pattern): exploring twice on consecutive days in a region
  where one non-fight beat is forced (set others' weight via a test GameData copy or seed) does not give the same beat twice.
