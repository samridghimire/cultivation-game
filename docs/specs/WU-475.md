# WU-475: A crowd you can read

Role: world-ui. Reference: Stardew Valley and Wandering Sword, where a crowded square shows only the name you are next to.
Mechanics only.

## What the planner saw (2026-11-07 12:10, `screenshot_first_hour.gd -- --festival`, 1280x800)
1. At the Dragon Boat square seven name labels pile on each other ("Yelu Xiyao", "Xiao Ling (Childhood Friend)",
   "Hunter Ma (Village Hunter)" over "Dragon boat race today", "Zhao Juan", "Elder Mo (Retired Cultivator)", "Ye Shiyi
   (Qi Refining, 1st Layer)"). LabelLayout nudges and fades, but with this many figures most labels stay overlapped.
2. The interact chip "[E] Shen Xing (Qi Refining, 1st Layer)" draws at the top of the screen (about x 190, y 45, over the
   status card) while the player stands in the crowd at the bottom. Shen Xing is not visible near the player. Either the
   target's virtual label rect (WU-474 `label_rect("")` for a hidden label) is transformed wrongly, or `prompt_rect`'s
   clamped fallback lands far from the target when every try hits an occupied rect.

## Build
1. **Crowd labels.** In the world's label pass (src/world/label_layout.gd is pure; the caller is in world.gd / the
   interactables that draw labels): when more than 3 NPC labels lie within 160 px of each other on screen, show the label
   of the current interact target and of the nearest named villager to the player only; the others fade to alpha 0 and
   come back when the crowd thins (tween 0.15 s; instant under reduce_motion). Place labels (stalls, landmarks such as
   "Dragon boat race today") keep priority over generated-villager labels. Put the selection in a pure static helper
   `LabelLayout.crowd_keep(rects: Array[Rect2], priority: Array[int], focus: int, radius: float = 160.0, max_shown: int = 3) -> Array[bool]`.
2. **Prompt by its target.** The chip must sit within 120 px of the target figure's screen position. If `prompt_rect`
   cannot find a free spot near the label, place it just above the figure (allowed to overlap faded labels) instead of the
   clamped first try; if the target is off screen, use the bottom fallback. Find and fix the wrong label rect if that is
   the cause (check `target.label_rect("")` for a hidden label against the figure's position).
3. **Labels under the key bar.** World labels whose rect intersects the bottom key-hint bar or the message log rect are
   nudged up above it (LabelLayout blockers already exist; pass those two HUD rects as blockers).

## Tests
- `crowd_keep`: 7 rects in a 150 px cluster keep focus + nearest + place labels (max 3); a spread-out set keeps all.
- `prompt_rect` / the new placement helper: with every try blocked, the chip is within 120 px of the target point.
- A blocker rect at the bottom pushes an overlapping label above it.
