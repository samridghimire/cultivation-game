# ART-011: The artifact remembers what fed it (systems)

Reference: Tale of Immortal's treasure panel that tells you what it grew from (mechanics only).

## Why
ART-009 made the artifact drink your progress, but the player only ever sees one line a day ("The artifact drinks the change
in you (+20 energy, 55 in all)") and an energy bar. Nobody can tell *what* fed it or what to do to feed it more. WU-527
(world-ui, after this task) will show this on the artifact screen; this task builds the core data and a Today line.

## Core (src/core)
1. `CharacterData.artifact_gains: Array` (of Dictionary `{"day": int, "source": String, "amount": int}`), newest last,
   at most `ArtifactFunctions.GAINS_KEPT := 6` entries. Add to `to_dict`/`from_dict` with default `[]` (old saves load
   empty; no SAVE_VERSION bump needed) and to the every-field save test.
2. `ArtifactFunctions.record_gain(c: CharacterData, source: String, amount: int, day: int) -> void`: ignore amount <= 0;
   if the last entry has the same `day` and `source`, add to it; else append; trim from the front to GAINS_KEPT.
   Sources: `stage`, `realm`, `first_win`, `discovery`, `secret_realm_floor` (the keys of data/artifact.json
   `energy.progress`), plus `stones` and `offering` (fed items).
3. Give `grant_progress` (and through it `drink_progress`, `drink_first_win`) an optional trailing `day: int = -1`;
   when `day >= 0` it calls `record_gain`. `feed()` gets the same optional `day` and records `stones` for spirit stones,
   `offering` for anything else. Existing callers without a day keep working (tests unchanged).
4. `ArtifactFunctions.gain_text(data: GameData, gain: Dictionary) -> String`: e.g. "+15 a new stage", "+60 a new realm",
   "+5 first win over a foe", "+5 a discovery", "+10 a secret realm floor", "+100 spirit stones", "+12 an offering".
   When `amount` covers several units, say so: "+30 two new stages" is not needed; "+30 new stages" is fine.
5. `ArtifactFunctions.energy_sources(data: GameData) -> Array[String]`: one short line per `energy.progress` key with
   value > 0, in the order stage, realm, first_win, discovery, secret_realm_floor, then "1 per spirit stone fed"
   from `energy.stone_energy`. E.g. "+15 each new stage". Pure, data-driven (a test changes the data and sees the text change).
6. `ArtifactFunctions.next_seal_line(c, data, flags) -> String`: "Artifact: 55 / 100 energy toward Storage Space" for the
   cheapest sealed function whose realm/function prerequisites are met (reuse whatever WU-524's `status()` / the energy bar
   uses to pick "the cheapest seal"; do not duplicate the choice), "" when every seal is open or none is reachable yet.

## GameState (src/autoload/game_state.gd)
- Pass `GameClock.total_days` into `drink_progress` (~line 4537), `drink_first_win` (~4079) and the feed actions, so every
  gain is recorded. The once-a-day log line stays exactly as it is.

## Guidance / Today
- The journal's Today tab (where the almanac/season blocks are built) gets `next_seal_line` as one line in its existing
  "you" / progress block, only when the line is non-empty and the artifact has at least 1 energy (no line on day 1).
  Do not add it to the HUD's Next steps (ART-009's hum hint already covers "ready").

## Tests (tests/unit/test_artifact_gains.gd)
- record_gain merges same day + source, appends otherwise, keeps 6, ignores 0.
- A stage breakthrough through GameState records a `stage` gain with today's day; a first win records `first_win`; feeding
  10 stones records `stones` 10.
- energy_sources follows data (edit `energy.progress.stage` to 20 in a test copy -> "+20 each new stage").
- next_seal_line: "" for a fresh character with 0 energy is allowed by the Today rule; with 55 energy at Qi Refining
  -> mentions Storage Space and 55 / 100; with all seals open -> "".
- Save round-trip keeps artifact_gains; a dict without the key loads [].
